# 滴滴出行 8.0.14

研究对象是官方版本 `8.0.14`、versionCode `1208001404`、包名
`com.sdu.didi.psnger` 的 ARM64 APK、8 个 DEX、资源、随包分发的 native 库和
代码路径中的服务端接口定义。打车链路与 AI 叫车功能全部采用**静态只读**调查：
未构造请求、未登录账号、未触发下单或支付。另对自有 Android 设备做**只读**
运行态核对：只经应用私有数据目录读取数据库 schema 与已落盘文件，未写入设备、
未发起任何网络请求。

样本 SHA-256：
`e1b3752697f16fcad51688ce44b1a8dc5f336ab8569f226da0548df4059ab02e`，
大小 `76,989,224` 字节，ZIP 完整性通过；`classes.dex`…`classes8.dex` 共 8 个。

## 覆盖范围

- `OkHttpRpc` 请求管线、43 个请求头、211 个主机与查询/正文合并格式。
- 认证三元组：`secdd-authentication`、业务 `token`、`wsgsig` 签名的精确构造。
- WSG 签名、`wsgenv` 环境采集、WAF 522 挑战、接口加密（AES-128+GZIP）的算法闭包。
- 上传与下载的具体字段、分片协议、RN/Hummer 包与资源缓存落盘格式。
- 登录、验证码、扫码、人脸、MFA 与票据刷新的接口族与字段。
- 权限声明、导出组件、隐私同意链、越权/提权/超范围采集判断。
- 打车链路的入口、场景页、估价、下单、进行中与结束态静态路由。
- AI 叫车（`llm_assistant`）的开启条件、SSE 协议、撮合状态机与功能面。
- 52 个 JADX 残留方法的逐项归类（无未解释加密实现）。
- 只读设备端 17 个真实数据库的 schema、行数与落盘格式核对。

## 研究边界

客户端静态分析可以证明“代码能采集什么、在何条件触发、写入哪个字段、调用哪个
端点”，不能证明服务端实际保存多久、如何评分或采取何种处罚。报告把客户端事实、
跨版本可比事实和服务端不可见部分严格分开；不提供登录绕过、签名伪造、下单攻击
或批量抓取方法。native 风控代码已按 JNI 注册地址、控制流平坦化状态机、数据段
解码表、签名网关调用链和 Base64 字母表逐项还原；`libsignkey.so` 返回硬编码
DES 密钥，`libdexvmp.so` 仅承担联通认证 SDK 的反射虚拟机，不参与打车请求签名。
