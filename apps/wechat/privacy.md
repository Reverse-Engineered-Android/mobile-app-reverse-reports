# 数据收集、告知与同意边界

## 结论

将 8.0.78 的 Manifest/静态证据、既有风险采集证据，与 2026-10-02 获取的
《微信隐私保护指引》（更新/生效日期 2026-08-17）逐项对照后：

1. **设备型号、AndroidID/OAID、IP、软件版本、SSID/BSSID、网络质量、
   加速度传感器、操作/服务日志，以及应用安装卸载、正在运行进程和内存
   数据，当前政策已明确披露。** 这些类别不能继续标成“完全未告知”。
2. **通讯录、位置、相机、麦克风、相册等敏感权限，政策明确声明不会默认
   开启，只在用户明确同意的范围内、为相应功能调用。** Manifest 请求本身
   不证明这些数据已被读取或上传。
3. **IMSI、SIM country、基带、序列号等更细粒度设备/电信字段，当前政策
   文本没有逐字列名。** 既有静态证据证明部分读取路径可达，但尚缺
   “同意前采集”“每次上传非空”“服务端保留”三段证据，因此结论是
   **存在告知颗粒度缺口/需动态确认，而不是已确认违法采集**。
4. **本轮没有发现已证实的首启同意前网络上传。** 当前证据以静态可达性为
   主；要关闭这个问题，需要在拒收/撤回/接受三组受控状态下抓取网络并比对
   时间线。
5. **没有把广泛风控能力写成已确认的“越权”。** 政策与代码能力可以证明
   收集范围较宽；是否超范围使用、是否绕过同意、服务端如何使用，仍需运行
   时流量和后端证据。
6. **2026-10-02 真机只读快照补齐了“当前授权状态”这一段：** 10 项用户敏感
   权限已授予、6 项未授予；位置、相机、麦克风、剪贴板在 AppOps 层被限制为
   `foreground`，联系人、短信、电话状态、历史媒体等默认 `ignore`。这与政策
   “敏感权限不默认开启”的表述方向一致，但**授权状态仍然不等于已调用或已上传**。

## 政策已明确覆盖的类别

政策 1.2 节明确列出：

- 设备型号、操作系统；
- AndroidID/OAID 等设备标识符；
- 登录 IP、微信版本号；
- 接入网络方式、类型和状态，包括 SSID/BSSID；
- 网络质量、加速度传感器；
- 操作日志、服务日志；
- 为恶意程序防护而收集的应用安装卸载信息、正在运行的进程信息或内存数据。

政策 1.42 节还说明传感器只在特定功能必要范围内使用；导言第 6 点说明
通讯录、位置、相机、麦克风、相册等敏感权限不会默认开启，只在明确同意
后按同意范围调用，并可在“设置—更多—系统权限”查看和管理。

因此，既有报告中 AndroidID/OAID、SSID/BSSID、进程/内存、安装信息、加速度
传感器等能力，应归类为“政策已披露的宽采集”，而不是“未告知”。

## 需要继续确认的颗粒度缺口

既有 `evidence/risk-source.md` 还记录了 IMSI、SIM country、Android
ID/device ID、设备变化检测，以及 RiskScanner 对 root、PATH、setuid、
debugger/recovery 等环境的检查。当前政策文本：

| 字段/行为 | 静态证据 | 当前政策逐字披露 | 当前结论 |
| --- | --- | --- | --- |
| AndroidID/OAID | 有 | 有 | 已披露 |
| SSID/BSSID | 有 | 有 | 已披露 |
| 应用安装、进程、内存 | 有 | 有 | 已披露 |
| 加速度/传感器 | 有 | 有，限定必要范围 | 已披露，仍需验证调用范围 |
| IMSI / SIM country | 有读取路径 | 无 | 颗粒度缺口，待确认上传与同意 |
| 基带/序列号类字段 | 风控结构有线索 | 无逐字列名 | 待确认实际采集与上传 |
| 截屏/录屏状态 | 既有风控报告提及 | 当前文本未逐字列名 | 待确认调用、上传与告知 |
| 剪贴板 | 本轮微信样本未形成证据链 | 政策文本未发现明确条目 | 不作结论 |

“政策未逐字列名”不自动等于违法；设备标识、安全日志或电信状态可能被
上位类别覆盖。但若实际上传这些字段，仍应在摘要、权限记录或功能提示中让
用户能理解其存在、用途和范围。

## 真机运行时授权状态

| 状态 | 权限 |
| --- | --- |
| 已授予（均带 `USER_SET`） | `ACCESS_FINE_LOCATION`、`ACCESS_COARSE_LOCATION`、`CAMERA`、`RECORD_AUDIO`、`READ_MEDIA_VISUAL_USER_SELECTED`、`NEARBY_WIFI_DEVICES`、`BLUETOOTH_CONNECT`、`BLUETOOTH_ADVERTISE`、`BLUETOOTH_SCAN`、`POST_NOTIFICATIONS` |
| 未授予 | `READ_CONTACTS`、`READ_MEDIA_IMAGES`、`READ_MEDIA_VIDEO`、`READ_EXTERNAL_STORAGE`、`ACTIVITY_RECOGNITION`、`ACCESS_MEDIA_LOCATION` |

其中 `READ_CONTACTS`、`ACTIVITY_RECOGNITION`、`ACCESS_MEDIA_LOCATION` 没有
`USER_SET`，说明用户尚未对该权限做过选择；`READ_MEDIA_IMAGES` /
`READ_MEDIA_VIDEO` 为 false 且带 `USER_FIXED`，同时
`READ_MEDIA_VISUAL_USER_SELECTED=true`，符合 Android 14+ 的“仅选择部分
照片视频”状态。

AppOps uid 级模式中，位置（粗/精）、相机、麦克风、剪贴板读写为
`foreground`；联系人、通话/日历/短信、电话状态与号码、外部存储、历史媒体、
媒体位置、活动识别等为 `ignore`。

**关键限制：**

1. 这是**授权状态**快照，不是调用记录，更不是网络上传记录；
2. AppOps 的 `time=`/`rejectTime=` 是读取时刻的相对增量，采集中同一字段在
   两次相隔约 15 秒的只读读取间就发生位移，因此本报告不把任何时间戳用作
   微信采集行为的证据；
3. 本轮没有抓取网络流量，也没有在拒收/撤回/接受三组状态间做对照。

详见 [`evidence/phone-runtime.md`](evidence/phone-runtime.md)。

## 同意与权限记录

静态证据显示微信资源包含“个人信息与权限管理”“小程序中的个人信息与
权限”“系统权限”等入口，并提供撤回同意和统一管理界面。该界面能降低
告知不足的风险，但不能单独证明每次采集都在对应同意之后。

本轮缺少以下动态证据：

1. 首次启动、拒绝隐私政策、接受隐私政策三个状态的网络流量；
2. 危险权限实际 API 调用时间线（授权状态已拿到，调用时间线仍缺）；
3. 撤回通讯录、位置、剪贴板或传感器权限后的停止行为；
4. 风控字段是否在未使用对应功能时仍上传；
5. 服务端接收、保留和用途说明。

因此，隐私审计的最终状态为：

- **已披露的宽采集：确认；**
- **更细字段的告知颗粒度缺口：确认存在；**
- **同意前采集/上传、实际超范围使用、服务端违法处理：未确认。**
