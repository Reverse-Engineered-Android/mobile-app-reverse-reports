# 小红书 9.37.0 算法深挖：shield 外层、定制 H 与 type 6/7 会话变换

本文给出 shield 的完整字节布局、已验证的密码学组件，以及每个组件的恢复程度。详细论证见 [crypto.md](crypto.md)。

## 1. 外层（已验证）

```text
P      = u32be(1) + u32be(app_id) + u32be(1)
       + u32be(len(build)) + u32be(len(device_id)) + u32be(16)
       + build + device_id + digest16
blob   = u32be(4 | (token_type << 16)) + u32be(1)
       + u32be(len(P)) + u32be(len(P)) + RC4(key, P)
shield = "XY" + base64(blob)
```

| 项 | 值 |
| --- | --- |
| RC4 key | `.rodata:0x13d9e` 的 ASCII 串，13 字节（abort 消息串被复用为密钥） |
| RC4 代码 | `0x4b658`–`0x4b9e4`（KSA/PRGA，S 盒栈上构建） |
| 装配入口 | `0x4b3d0` |
| 分派 | `0x467dc` 按 `token_type` 选择摘要变体 |
| 首轮无会话上下文时 | `digest16` 可为全零 |
| 曾疑似的 `35 16 11` | RC4 密钥流前三字节（`P` 前 3 字节为 0 直接透出），**不是** AES-ECB 标志 |
| 已否定的假设 | HMAC-SHA 系、SHA-384、AES-ECB |

证据等级：**已验证**（两组合成向量逐字节比对）。公开脚本通过环境变量传入 key，不内置原值。

## 2. 摘要 `H`（已完整恢复）

结构由三个函数的参数与输出长度确定（`0x7f224` 取 key、`0x7feec` 吸收请求、`0x8001c` 输出 16 字节）：

```python
K64      = token_payload[:64]
inner    = H(bytes(a ^ 0x36 for a in K64) + request_bytes)
digest16 = H(bytes(a ^ 0x5c for a in K64) + inner)
```

`H` 是定制 MD5 族变体：

| 项 | 差异 |
| --- | --- |
| IV | 逆序存储 `[0x10325476, 0x98badcfe, 0xefcdab89, 0x67452301]` |
| K16 / K19 / K29 | `0xf6002500` / `0xe90001aa` / `0xfc010010` |
| K39 ↔ K40 | 互换 |
| K41 ↔ K42 | 互换 |
| 第 63 轮 | 以块入口上下文状态作累加器 |
| c63 | 不进摘要 |

64 轮调度、状态更新与 Finalization 已全部恢复。验证：

```
zero_block    e68e2c1e9fffb2a34fc55055f8dc9126
inner_digest  0333710ea360d55803703522349e1a88
outer_digest  91653d232769b94c0a97c334119f2da0
vectors=3 mismatches=0
```

证据等级：**已验证**。

## 3. token type 与 type 6/7 会话路径

- token type 1–5 对应不同定制哈希变体。
- type 6/7 走会话 token 派生/刷新：`0x46a14` → `0x50010` → `0x5a128`（type 7 另带 `time(NULL)` 低字节，入口 `0x5a264`）。

`0x50010` 的接口：

| 量 | 大小 |
| --- | ---: |
| 输入 payload | 64 字节 |
| 输入 key | 20 字节 |
| 输出 | 16 字节（4 个小端 32 位字） |

关键事实：

- 输出**同时**依赖 payload 与 key（全零 payload 下，key[0]=0x00 → `1bd84c72…`，key[0]=0xFF → `8dd6a7a0…`）。
- 区域内**没有** AES/SHA1/SHA256/SHA512/SM3/SM4/CRC32/PMULL 指令（各 0 条）。
- 区域内**引用 29 个 `.rodata` 对象**：16 张 16 字节序列表（内容 `n..n+15`，恰好铺满 `0x00`–`0xff`）+ 13 个常量对象。大常量同时以 `movz`+`movk` 内联出现，rodata 块是同一常量集供 SIMD 通路一次性加载的外部化副本。
- 所有表引用都是**整块向量加载**（`ldr qN` 16 字节 / `ldr dN` 8 字节）；区域内 `tbl`/`tbx`/`ld1 {vN.16b}` 查表 **0 处**，动态实测 `.rodata` 字节级（size=1）访问 **0 次** ⇒ 这 16 张表是**常量向量池**，不是被 key 索引的 S 盒。
- `.rodata` 读钩子动态确认：两组输入下 16 张表**全部被真实读取**，属热路径数据。
- 区域内**不引用** K 表族（`0x94710`/`0x94810`/`0x94910`/`0x94a10` 共 4 张 64 字表，服务定制 H 的 type 1–5（type 1/2 复用同一张）；其中 `0x94710` 与未修改的 MD5 T 表 64/64 一致，另三张分别只有 6/64、3/64、3/64 槽相同）、定制 H init 的 IV（`0x15ca0`）、`0x4c0c8` 使用的标准序 IV（`0x15d40`）与 SHA-1 `H4`（`0x15e70`）；`0x15000` 起的 libc++ 字符串区紧邻常量池但**不在**引用清单内。
- 区域含 504 处寄存器间接跳转 = CFF 平坦化；`0x91868` 的 8 项跳转表（`.rela.dyn` 逐槽填充）对应 8 个独立算法块。
- 每轮块索引来自 `ldrb w9,[x20]` + `and x9,x9,#3`，`x20` 是栈帧指针 ⇒ 该选择子是**状态机块索引**，不是直接把 key 当算法选择子。
- **但控制流整体仍随输入变化**：10 组输入下实际执行到 337 个不同间接目标（其中相邻 4 组为 241 个），间接跳转次数 283–2 861，指令数 4 889–42 708；8 个顶层块中仅 2 个在全部 10 组输入中被进入。所以“CFF 只做等价路径随机化”只说了一半——块选择由数据相关条件驱动。
- 末尾 `0x59f84`–`0x5a124` 是 16 个按索引绑定的字节置换器（16/20/28 字节；读 `x0[i]` 与常量及下标混合后写 `x0[i+0x14]`），已逐条读出并列表；动态 trace 确认它们被真实调用。
- 字节级依赖矩阵实测：64/64 payload 字节与 20/20 key 字节**全部**影响输出，且 16/16 输出字节**全部**受影响 ⇒ 无装饰性输入。

合成向量与扩散统计见 [crypto.md](crypto.md) §4.5、§4.6。

单 trace 符号化 lift（`re/xyass_lift50010.py` + `re/xyass_type6_ref.py`）经修正对比宽度后实测 **4/4 mismatch**，对训练轨迹外的输入不成立，原因是上述数据相关控制流；因此**不作为参考实现**。

证据等级：**接口、数据范围、结构、常量集、表清单、动态可达性、确定性向量均已固化**。缺的是覆盖全部 CFF 路径的统一逻辑门级闭式（需逐块/逐路径 lift）。
