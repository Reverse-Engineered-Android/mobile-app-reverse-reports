# 哔哩哔哩 9.13.0

研究对象是官方版本 `9.13.0`、versionCode `9130500`、包名 `tv.danmaku.bili`
的 ARM64 APK、32 个 DEX、93 个 arm64 native 库、资源、配置与服务端接口定义。
搜索、直播、会员购、视频播放、缓存、互动和番剧 DRM 均采用**静态只读**调查；
未构造请求、未登录账号、未读取凭证，也未进行播放、登录、上传或风控实测。
另对自有设备做**只读**核对：只读取数据库 schema、落盘格式与聚合数量。

样本 SHA-256：
`d8e74cf3ce4e4332af75920035590979e4347938c65a6d2fc73627b0c132d98e`，
大小 `218,480,895` 字节；设备端 APK 与本地样本哈希一致。

## 覆盖范围

- HTTP 公共参数、请求头、JSON/表单/gRPC/protobuf 报文和网关调用链。
- `appkey`/`mobi_app`、`access_key`、buvid、会话 Cookie 与三条请求签名路径。
- 上传、离线下载、资源缓存、播放历史和网络统计的数据范围。
- 74 个权限、87 个导出组件、外部包查询面、隐私告知与数据最小化判断。
- Gripper 风控 36 个判定器、121 个字段码、GAIA 混合加密、风险上报和本地决策树。
- `libbili.so` 字符串解密、JNI 注册、appkey 表、签名算法和 native 风控签名。
- 搜索、直播、会员购、播放、缓存、互动、Widevine/Bilibili DRM 静态流程。
- 有 DRM 与无 DRM 的高播放番剧示例；仅基于静态资料，未请求片源。
- 所有风控相关密码学与混淆实现；不存在未解释的加密或混淆项。

## 研究边界

客户端静态分析可以证明代码能采集什么、在何种条件下触发、写入哪个字段和调用哪个端点；
不能证明服务端保存时长、评分阈值、内容授权范围或处罚策略。报告严格区分
“客户端具备能力”“样本中已观察到”与“实际被利用”，不提供登录绕过、签名伪造、
DRM 绕过、批量抓取或规避服务端风控的方法。
